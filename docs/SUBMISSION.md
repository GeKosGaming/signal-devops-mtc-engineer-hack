# Сдача: обязательный контроль до отправки

Условие требует публичный Git-репозиторий без авторизации, решение в main и ZIP/RAR с двумя файлами: `Ссылка.txt`, содержащим только ссылку, и `Паспорт.pdf` (либо допустимый DOC/DOCX). Архив — не более 18 МБ, паспорт — не более 4 страниц/15 МБ, имя архива — фамилия при регистрации.

В приложенном документе срок — **4 октября 23:59**, и изменения основной ветки после него запрещены. **Год и часовой пояс в этой формулировке не приведены**; уточнить их на странице конкурса. Не трактовать локальные часы компьютера как официальный срок.

## Последовательность без фиктивных доказательств

1. Клонировать main и на выделенной Ubuntu 24.04 выполнить bootstrap. Образы уже закреплены digest, оба chart находятся в vendor; проверить их SHA-256. При изменении версий осознанно выполнить `make lock`, `make vendor`, `make render`, `make static` и commit. Текущие зависимости заново получать не требуется.
2. Выполнить deploy/verify/acceptance/demo. Исправить реальные ошибки и повторить. Если acceptance не проходит, **нельзя заявлять подтверждённую Ubuntu-поддержку**. Паспорт обновлён по успешному Ubuntu-прогону; итоговая упаковка требует свежего acceptance финального commit.
3. Отредактировать паспорт: версия, реальная ОС, результаты и ограничения; сохранить PDF ≤4 страниц. Опубликованные доказательства можно отдельно скопировать в `evidence/published/` после просмотра на секреты/личные данные. Не копировать `.state/`, kubeconfig, private keys, пароли.
4. Публичный репозиторий: https://github.com/GeKosGaming/signal-devops-mtc-engineer-hack. Скрипт упаковки самостоятельно ничего не публикует. Основной branch — main. Сделать финальный code/docs commit, push до официального cutoff.
5. На том же финальном commit повторить `make acceptance`. Runtime-отчёт игнорируется Git и фиксирует именно этот HEAD. Затем запустить `make package` ниже. Не редактировать tracked-файлы между финальным acceptance и упаковкой. Если изменения понадобились — новый commit и новый acceptance до cutoff.
6. Проверить анонимный clone и отсутствие запроса авторизации. `package.py` сверяет публичный `refs/heads/main` с локальным HEAD, ОС/acceptance, свежесть lock, SHA-256 и побитовое содержимое chart в HEAD, чистоту worktree во время acceptance/упаковки и размер/число страниц PDF. Для числа страниц нужен `sudo apt-get install poppler-utils`.

```bash
make package REPO_URL=https://github.com/GeKosGaming/signal-devops-mtc-engineer-hack.git \
  SURNAME=Коннов PASSPORT=docs/Паспорт.pdf
```

Адрес и фамилия указаны по данным участника; репозиторий создан публичным. Генератор принимает HTTPS clone URL публичного репозитория с проверенным main; main должен быть default branch. Откройте `submission/Коннов.zip`: там только URL в `Ссылка.txt` и PDF. Загрузить этот архив на страницу задания. Исходный ZIP проекта не соответствует двухфайловому формату сдачи.

## Что генератор сознательно не гарантирует

Он не может подтвердить регистрацию участника, правильность фамилии, официальный timezone/cutoff или постоянную публичную доступность до списка финалистов. Он не оценивает паспорт по существу и не доказывает отсутствие любых секретов в истории Git. Public main hash проверяется анонимно, но отсутствие секретов и сохранение публичного доступа остаются обязательной проверкой автора.

**После официального дедлайна основную ветку не менять**, даже ради косметики или документации: условие допускает дисквалификацию.
